## One grammar

In the system this book checks, a type is not a separate species. The type
of a term is another term, and that term has a type too. `fun x : T => x`
has type `(x : T) -> T`, which has type `Sort 1`, which has type `Sort 2`.
The nodes called sorts are where the regress is organized: `Sort 0`,
abbreviated **Prop**, holds propositions; `Sort 1`, abbreviated **Type**,
holds ordinary data types; `Sort (l+1)` holds `Sort l` [R: T-SORT](RULES.md#t-sort).

TypeScript has the bottom two rungs of this ladder and stops. `number` is
a type; `Array` is not — it is something that *makes* a type when you
hand it one, and TypeScript gives you no way to write down what `Array`
itself is, or to quantify over all such things. Here you can: `Array` is
an ordinary term whose type is `Type -> Type`, that type is a term whose
type is `Sort 2`, and the ladder keeps going. One grammar all the way up
is what buys that.

Why not stop the regress with `Sort : Sort`? Because that one equation
makes the system inconsistent: Girard's paradox builds, inside any such
system, a well-typed term proving falsehood — the type-theory rendering of
"the set of all sets that do not contain themselves". The ladder is not
bureaucracy. It is the fix, and it has to go all the way up.

## Levels are a little language

The rung numbers, called **levels**, form their own small grammar: zero, a
successor `l+1`, a maximum `max(l1, l2)`, a variable (so a declaration can
be level-polymorphic — one definition usable at every rung), and one
strange operation, `imax`:

$$\mathrm{imax}(l, 0) = 0 \qquad \mathrm{imax}(l, m+1) = \max(l, m+1)$$

Because levels contain variables, equality of levels is not equality of
numbers. The kernel decides it syntactically: normalize both sides —
flatten the maxes, sort the operands, drop dominated entries — and compare
[R: LVL-NORM](RULES.md#lvl-norm). Beside it sits a separate *inequality*
judgment — a relation the checker decides — a syntactic descent through
max, imax, and numeric offsets [R: LVL-LEQ](RULES.md#lvl-leq). The
published theory specifies that inequality with a case split on every level
variable, trying it at zero and then at a successor; the kernel implements
the cheaper descent instead, which refuses some true inequalities and
accepts no false ones. Its one caller is the universe bound that chapter 6
puts on new data declarations. These two functions are fiddly, heavily
tested, and entirely mechanical; the interesting rule is the one that uses
imax.

## The pi rule, and why imax

A function type lives in the universe of its parts. The rule below is the
first written with premises over a bar: read it as "if the judgments above
the line hold, the conclusion below holds", and read Γ, x:A as the context
Γ extended with *x* of type *A*:

$$\frac{\Gamma \vdash A : \mathrm{Sort}\ l_1 \qquad \Gamma, x{:}A \vdash B : \mathrm{Sort}\ l_2}{\Gamma \vdash (x:A) \to B\ :\ \mathrm{Sort}\ (\mathrm{imax}(l_1, l_2))}$$

[R: T-PI](RULES.md#t-pi) with [R: LVL-IMAX](RULES.md#lvl-imax) doing the work. Take the most ordinary
statement in mathematics: *for every number n, n + 0 = n*. Its conclusion
is a proposition, so it belongs in Prop. Its domain is the numbers, which
are data and live one rung up. If the rule used `max`, the finished
statement would land in `Type` — and every theorem that quantifies over a
data type would stop being a proposition. `imax` says: if the *result* is
a proposition, the whole function type is a proposition, however large the
domain. Prop absorbs.

The same collapse is what lets a proposition quantify over *all*
propositions — `(p : Prop) -> p` stays in Prop rather than climbing out of
it. (That particular statement is often introduced as a definition of
falsehood. It is not one here: in this system `False` is declared, not
encoded, and chapter 6 is where declarations like it are checked.) The
technical name for the collapse is *impredicativity*, and it is confined
to Prop; the data-carrying rungs stay predicative, and chapter 6 shows the
rule that polices the border when data types are declared.

The exercise below runs both versions of the rule side by side. The wrong
one does not crash — it just quietly reclassifies ordinary theorems out of
Prop. A kernel bug of this kind refuses true theorems rather than
accepting false ones, and telling those two failure modes apart becomes
the organizing question of chapter 13.

## Try it

```ts
// Chapter 3 — Types are terms.
// The universe ladder, and the one function that holds Prop in place.

// Concrete levels are enough to see the shape (the real thing also has
// level variables, max, and a normalizer).
// Sort 0 is Prop. Sort 1 is Type. Sort 2 is the type of Type. And so on.

function imax(l1: number, l2: number): number {
  // imax collapses when the right side is zero: a family of propositions
  // is a proposition, no matter how big the domain is.
  return l2 === 0 ? 0 : Math.max(l1, l2);
}

// The typing rule for a function type (x : A) -> B:
//   A : Sort l1    B : Sort l2 (under x)
//   -------------------------------------
//   ((x : A) -> B) : Sort (imax l1 l2)
function piSort(l1: number, l2: number): number {
  return imax(l1, l2);
}

function name(l: number): string {
  if (l === 0) return "Prop";
  if (l === 1) return "Type";
  return `Sort ${l}`;
}

// The everyday case. `n + 0 = n` is a proposition, so l2 = 0; the domain
// Nat is a data type, so Nat : Sort 1 and l1 = 1. A statement ABOUT
// numbers must still be a statement.
console.log(`(n : Nat) -> n + 0 = n : ${name(piSort(1, 0))}`);

// The self-referential case: quantifying over ALL propositions...
// domain Prop : Sort 1, so l1 = 1; body p : Prop, so l2 = 0.
console.log(`(p : Prop) -> p        : ${name(piSort(1, 0))}`);

// ...and it lands back in Prop too. That is impredicativity. Compare a
// quantifier over Type: (A : Type) -> A has l1 = 2 and l2 = 1.
console.log(`(A : Type) -> A        : ${name(piSort(2, 1))}`);

// A chain of quantifiers only climbs as high as its tallest domain:
console.log(`(A : Type) -> A -> A   : ${name(piSort(2, piSort(1, 1)))}`);

// With max instead of imax, Prop stops absorbing:
function piSortWrong(l1: number, l2: number): number {
  return Math.max(l1, l2);
}
console.log(`n + 0 = n, with max    : ${name(piSortWrong(1, 0))}`);

// To break it: that last line IS the break. A kernel whose pi rule uses
// max instead of imax says that `(n : Nat) -> n + 0 = n` lives in Type,
// not Prop — every theorem that quantifies over a data type stops being
// a proposition, and the chapter 5 rule that makes any two proofs of a
// proposition interchangeable no longer applies to any of them.
// The dual mistake — letting Sort l : Sort l — accepts everything,
// including a proof of False, by Girard's paradox. The ladder is not
// decoration; it is the wall between those two failures.

export {}; // keeps this file a self-contained module
```

Expected output:

```text
(n : Nat) -> n + 0 = n : Prop
(p : Prop) -> p        : Prop
(A : Type) -> A        : Sort 2
(A : Type) -> A -> A   : Sort 2
n + 0 = n, with max    : Type
```
