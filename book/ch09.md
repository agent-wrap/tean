> **Claim.** Rank failures by what each one blocks, and rank again after
> every fix, because the ranking moves.
>
> **You are here.** The checker reads real exports (chapter 8). Now it
> meets 199 of them at once. **Next:** Chapter 10 — The cost.

## Round one: 152 of 199

The first full run of this project's checker against the arena suite
accepted 152 of 199 files. All 72 files that must be refused were
refused — the refusing half of a kernel is the easier half to port,
because every rule in chapters 5–7 was written as a refusal. The
accepting half failed 47 times.

The wrong next move is to open failure #1 and start debugging. The right
move is a tool that groups failures by *root*: follow each failed
declaration's blocked chain down to the first declaration that actually
failed, and count how many tests each root blocks. Day one's table had
exactly two rows: one root blocked 46 of the 47; everything else, one.

## The underscore

That root was one character wide. A universe-polymorphic recursor gets a
fresh level variable for its motive; fresh means `u`, or — when the
declaration already uses `u` — `u` with a counter appended by the
kernel's `append_after`, which inserts an underscore: `u_1`. The port
wrote `u1`. Every level annotation of every derived universe-polymorphic
recursor differed from the export, the derive-and-compare rule of
chapter 7 refused each one [R: WF-REC-DERIVE], and 46 tests fell over.
The fix was read out of the real bytes: the export of `PUnit.rec` lists
its level parameters, and they spell `u_1`.

Nothing static catches this class of bug. The typechecker was green, the
lint was green, the unit tests were green — only an oracle that is not
the author, holding bytes the author never wrote, could see it. That is
the chapter's claim applied to itself: the *measurement* is the review.

## Round two, and the moving ranking

With the underscore fixed: 185 of 199, and a fresh ranking. The new top
root: recursor derivation must strip `outParam` and its sibling type
annotations from binder types before making locals — the kernel's
`consume_type_annotations`, found by diffing the derived `HAdd.rec`
against the exported bytes, worth ten tests. Then 195 of 199, and the
ranking moved again: everything left was resource exhaustion — stack,
memory, time — which is chapter 10's subject, because from the outside a
crash and a timeout look identical, and the notebook has the scar to
prove it.

The discipline generalizes past this project. A failure list is a
dependency graph, not a to-do list; its visible size says nothing about
the work remaining. Rank, fix the root with the highest blocked count,
re-run, re-rank. Day one needed exactly three ranked fixes to go from
152 to 195.

## Try it

```ts
// Chapter 9 — The failure ranking.
// One underscore, 46 test failures, and the method that found it.

import { Name } from "../../src/kernel/name.ts";

// The kernel derives a FRESH universe variable for a recursor's motive.
// Fresh means: "u", unless the declaration already uses "u", in which
// case append a counter. The question a port must answer exactly:
// what string does appending produce?

// The guess a port naturally writes:
function appendAfterGuess(base: string, i: number): string {
  return `${base}${i}`; // u -> u1
}

// What the kernel's name::append_after actually does — src/kernel/name.ts
// ports it, and vendor/lean4-inductive.cpp calls it for this exact job:
const real = Name.simple("u").appendAfter(1).toString();

console.log(`guess       : ${appendAfterGuess("u", 1)}`);
console.log(`kernel      : ${real}`);
// The export of PUnit.rec names its motive level u_1. A derived recursor
// named u1 differs from the exported one in every level annotation, so
// the compare refuses — once per universe-polymorphic inductive type.
console.log(`export says : u_1 (PUnit.rec levelParams, read from real bytes)`);

// The method that found it. Day one, round 1: 47 good tests failed.
// Rank the failures by shared ROOT, not by name, and fix the top root.
interface Failure {
  root: string;
  blocked: number;
}
// The real day-one table, from docs/NOTEBOOK.md (2026-10-15):
const round1: Failure[] = [
  { root: "append_after underscore (u1 vs u_1)", blocked: 46 },
  { root: "other", blocked: 1 },
];
const round2: Failure[] = [
  { root: "outParam not stripped in recursor locals", blocked: 10 },
  { root: "resource limits (stack, memory, time)", blocked: 4 },
];

function top(fs: Failure[]): string {
  const best = [...fs].sort((a, b) => b.blocked - a.blocked)[0];
  return best === undefined ? "none" : `${best.root} (blocks ${best.blocked})`;
}

console.log(`round 1 fix : ${top(round1)}`);
console.log(`round 2 fix : ${top(round2)}`);

// To break it: sort round2 by root name instead of blocked count, the
// way an alphabetized issue tracker would. The resource limits come
// first, a week disappears into stack tuning, and ten tests that one
// line would fix stay red. Rank by what each failure BLOCKS, and rank
// again after every fix, because the ranking moves.
```

Expected output:

```text
guess       : u1
kernel      : u_1
export says : u_1 (PUnit.rec levelParams, read from real bytes)
round 1 fix : append_after underscore (u1 vs u_1) (blocks 46)
round 2 fix : outParam not stripped in recursor locals (blocks 10)
```
