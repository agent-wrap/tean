> **Claim.** Agreeing with a kernel means agreeing with its conventions,
> and the conventions are only written down in its source.
>
> **You are here.** The checker reads real exports (chapter 10). Now it
> has to agree with the kernel on things no rule states. **Next:**
> Chapter 12 — The cost.

## Where a rule stops and a convention starts

The published type theory specifies the recursor of a data type up to
the naming of its bound variables and up to irrelevant decoration. That
is the right level of abstraction for a theory: names do not change what
a judgment means.

It is the wrong level for a checker, and chapter 8 is the reason. The
recursor is *derived and compared* [R: WF-REC-DERIVE](RULES.md#wf-rec-derive) — the kernel builds
its own and refuses the input's if the two differ. The moment an export
file writes a name down, that name is part of the interface, and a
disagreement about it is indistinguishable from a forged recursor. A
checker that implements every rule in the theory correctly and picks
different names agrees with the theory and refuses the library.

Two conventions carry essentially all of this weight.

## The fresh level variable

A universe-polymorphic recursor needs a level variable for its motive,
and it must be fresh — not already bound by the declaration. The kernel
takes `u`, and if `u` is taken appends a counter. The appending is done
by its name-freshening operation, which inserts an **underscore**: the
result is `u_1`, not `u1`.

Nothing in the theory says so, and string concatenation is the obvious
guess. The cost of the obvious guess is total and silent: the motive's
level variable appears in every level annotation of the recursor's type,
so a derived recursor named `u1` differs from the exported one
everywhere, for every universe-polymorphic type in the library at once.
The failure surfaces as a type error reported against someone else's
proofs.

## Annotations that mean nothing to a kernel

Lean's elaborator marks binder types with wrappers — `outParam`,
`semiOutParam`, `optParam`, `autoParam` — that direct instance
resolution and default arguments. They are elaboration-time instructions
and the kernel assigns them no meaning. They are also written into the
export, because the export is a dump of elaborated declarations.

So recursor derivation has to strip them before turning binders into
locals; the kernel has a dedicated operation for exactly this, applied
at exactly that point. A derivation that keeps the wrapper produces a
recursor whose binder types read `outParam Nat` where the export says
`Nat` — again a mismatch about nothing, again fatal to the comparison,
and again confined to the part of the library that uses instances, which
is most of it.

## What follows from both

Neither convention is deep, and that is the part worth keeping. The
interesting rules of chapters 1–9 are published, argued over, and proved
correct by people other than the implementor. The places a port actually
diverges are the ones *below* the theory's resolution, where the kernel
had to pick something and picked. There is no specification to read for
those. There is only the source, and an oracle that does not care what
you believed.

That is why the registry behind this book cites a symbol in the C++
kernel for every rule, and not only a section of the thesis. The thesis
is authoritative about what must be true; the source is authoritative
about what is actually being compared.

## Try it

```ts
// Chapter 11 — The conventions.
// Two pieces of kernel behaviour that no published rule mentions, and
// that a derive-and-compare checker must reproduce exactly.
// Run from the repository root: bun book/tryit/ch11.ts

import { Name } from "../../src/kernel/name.ts";
import { Const, App, ExprKind, consumeTypeAnnotations, type Expr } from "../../src/kernel/expr.ts";

// ---------------------------------------------------------------------
// 1. Freshening a universe-level name
// ---------------------------------------------------------------------

// A universe-polymorphic recursor needs a FRESH level variable for its
// motive. "Fresh" means `u`, unless the declaration already binds `u`,
// in which case a counter is appended. The question a port must answer
// exactly: what string does appending produce?

const plausible = (base: string, i: number): string => `${base}${i}`;
const actual = Name.simple("u").appendAfter(1).toString();

console.log(`string concatenation : ${plausible("u", 1)}`);
console.log(`Name.appendAfter     : ${actual}`);
console.log(`the export says      : u_1  (PUnit.rec levelParams, in the bytes)`);

// The underscore is not cosmetic. The recursor is derived and compared
// against the exported one (chapter 8), and the motive's level variable
// appears in every level annotation of that type. One wrong character
// and every universe-polymorphic inductive type in the library is
// refused — a type error reported against the *library*, for a
// disagreement about a name.
console.log(`derived type matches : ${actual === "u_1"}`);

// ---------------------------------------------------------------------
// 2. Annotations on binder types
// ---------------------------------------------------------------------

// Elaboration-time markers (outParam, optParam, autoParam,
// semiOutParam) survive into the export, wrapped around binder types.
// They carry no meaning for the kernel, and recursor derivation must
// strip them before making locals — otherwise the derived recursor's
// binders differ from the exported one's, again by nothing that matters.
const nat: Expr = new Const(Name.simple("Nat"), []);
const wrapped: Expr = new App(new Const(Name.simple("outParam"), []), nat);

const show = (e: Expr): string =>
  e.kind === ExprKind.App ? `(${show(e.fn)} ${show(e.arg)})` : (e as Const).name.toString();

console.log(`\nbinder type as exported : ${show(wrapped)}`);
console.log(`after consumeTypeAnnotations : ${show(consumeTypeAnnotations(wrapped))}`);
console.log(`a bare type is unchanged     : ${show(consumeTypeAnnotations(nat))}`);

// To break it: neither of these is reachable from the published type
// theory, which specifies a recursor's type only up to the naming of
// its bound variables. Once an export writes those names down, the
// naming is part of the interface — and the only normative statement of
// it is the kernel's source. That is why this book's registry cites a
// symbol in the C++ for every rule, and why chapter 14 insists on an
// oracle the author did not write.
```

Expected output:

```text
string concatenation : u1
Name.appendAfter     : u_1
the export says      : u_1  (PUnit.rec levelParams, in the bytes)
derived type matches : true

binder type as exported : (outParam Nat)
after consumeTypeAnnotations : Nat
a bare type is unchanged     : Nat
```
