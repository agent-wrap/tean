> **Claim.** Every number here was measured, and the two that matter
> point in opposite directions.

## Two numbers

On a real library, this checker is fast. The `init` corpus — Lean's own
prelude, 59,623 declarations, 6.5 million lines of export — is accepted
whole in **22.2 seconds**. The official C++ kernel, on the same machine
and the same file, takes **35.1 seconds**. A TypeScript port, running on
a garbage-collected runtime, checks the real prelude faster than the
kernel it was ported from.

On one adversarial test, it is catastrophic. The largest magma test on
the arena board needs **48 GB of heap** here, against under 10 GB for
every other checker that passes it.

Both numbers are real and neither is the headline. The gap between them
is this chapter: the shapes that dominate a real library — shallow
terms, heavy constant unfolding, enormous numbers of small declarations
— are not the shapes an adversary writes, and a checker is tuned for one
or the other unless somebody measures both.

## The cache that must forget

Reduction rebuilds equal terms as fresh objects. A cache keyed on object
identity therefore misses forever: the term it is asked about is never
the term it stored, even when the two are the same tree. On one arena
test the difference between identity-keyed and structurally-keyed
caches is the difference between exhausting memory and finishing in 1.4
seconds — the exercise below shows the mechanism directly, in six lines.

The dual constraint is quieter. The hash must ignore *exactly* what
equality ignores — binder names and binder annotations
[R: DEFEQ-BINDING](RULES.md#defeq-binding) — or equal terms land in different buckets and the
cache never hits, silently, with no error anywhere. A hash finds a
candidate; equality decides.

## Unfolding is the hot path

A CPU profile of the hardest timing test puts a quarter of self time in
one closure, and it is not substitution: it is level instantiation,
performed on *every* delta unfold [R: RED-DELTA](RULES.md#red-delta). Unfolding a constant
means substituting the use site's universe levels into its value, and a
checker that redoes that work per occurrence pays for it everywhere,
because delta is the most common reduction in a real library by a wide
margin.

The fix is the cache the C++ kernel already keeps — unfolds memoized per
constant instance, its `m_unfold`. With it, that test runs in 4.2
seconds; without it, 10.6. The same economy governs beta: a whole
application spine is discharged in one substitution pass
[R: RED-BETA](RULES.md#red-beta), because one argument at a time re-walks the body
quadratically.

## Reading the exit, not the clock

The deep tests do not fail politely. A proof whose input tree is 128
nodes deep can reach a reduction depth of 14,520 — the depth is *made*
by computation, not read from the file, which is why no parser-level
limit can see it coming. The JavaScript engine this project tests under
pins about eight megabytes of stack (65,483 frames measured); the engine
it ships under, with the stack raised, holds 639,753; a worker thread
with a two-gigabyte stack holds 21,842,852, thirty-four times the main
thread's maximum. The substitution walk that needed more than the first
of those is an explicit-stack machine rather than a recursive one.

And the measurement discipline that matters more than any of those
numbers: from outside a process, a stack crash and a timeout are the
same silence. Read the exit code and the error stream, never the wall
clock. A checker that crashes on a forgery has not refused it, and a
harness that cannot tell the difference will report that it did.

## The ledger, with its open rows

Two rows are open, and the book does not get to close them by asserting
anything.

The 48 GB heap is the first. Bytes per node is the suspect — this
checker's expression nodes carry a cached hash, a loose-variable range
and two flags, and the magma test builds a great many of them — but the
heap profile that would convict it has not been taken.

The second is larger. On the `std` corpus, 104,050 of 104,056
declarations pass, and the run takes 13.5 minutes against the official
kernel's 60 seconds on the same machine. Profiling attributes the bulk
to symbolic evaluation inside bit-vector decision-procedure proofs: tens
of millions of reduction steps unfolding a hash-map insertion over free
variables, work the official kernel resolves without unfolding at all.
Which comparison it short-circuits, and where, is not yet known. That is
the top-ranked open question about this checker, stated here rather than
rounded off.

## Try it

```ts
// Chapter 13 — The cost.
// The cache experiment: identity keys miss what reduction rebuilds.

import { Name } from "../../src/kernel/name.ts";
import { type Expr, Const, App, exprEq } from "../../src/kernel/expr.ts";

// Reduction rebuilds equal terms as FRESH objects. Simulate that:
function build(): Expr {
  const f = new Const(Name.simple("f"), []);
  const a = new Const(Name.simple("a"), []);
  let e: Expr = a;
  for (let i = 0; i < 10; i++) e = new App(f, e);
  return e;
}

const first = build();
const rebuilt = build(); // equal tree, all-new object identities
console.log(`exprEq(first, rebuilt)    : ${exprEq(first, rebuilt)}`);
console.log(`same object?              : ${first === rebuilt}`);
console.log(`hashes agree?             : ${first.hash === rebuilt.hash}`);

// Cache 1: identity-keyed, the JavaScript default.
const identityCache = new Map<Expr, string>();
identityCache.set(first, "cached result");
console.log(`identity cache hit        : ${identityCache.has(rebuilt)}`);

// Cache 2: hash buckets + structural equality, as the kernel's expr_map.
class StructuralMap {
  private buckets = new Map<number, { k: Expr; v: string }[]>();
  set(k: Expr, v: string): void {
    const b = this.buckets.get(k.hash) ?? [];
    if (b.length === 0) this.buckets.set(k.hash, b);
    b.push({ k, v });
  }
  get(k: Expr): string | undefined {
    for (const e of this.buckets.get(k.hash) ?? []) {
      if (e.k === k || exprEq(e.k, k)) return e.v;
    }
    return undefined;
  }
}
const structuralCache = new StructuralMap();
structuralCache.set(first, "cached result");
console.log(`structural cache hit      : ${structuralCache.get(rebuilt) !== undefined}`);

// The measured consequence, both numbers in docs/NOTEBOOK.md: on the
// arena test `discarded-argument-match`, identity-keyed whnf, infer and
// defeq caches exhaust memory; structural ones finish in 1.4 seconds.
// Same algorithm. The only difference is the line above that can say
// "yes" to an object it has never met.

// To break it: make StructuralMap.get compare with === only, and watch
// the hit turn false. Then consider the quieter failure: a hash that
// includes what equality ignores (binder names, for instance) sends
// equal terms to different buckets, and the cache silently never hits.
// The hash must forget exactly what the equality forgets.
```

Expected output:

```text
exprEq(first, rebuilt)    : true
same object?              : false
hashes agree?             : true
identity cache hit        : false
structural cache hit      : true
```
