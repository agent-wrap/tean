## The format

A Lean library leaves the proof assistant through `lean4export`, as
NDJSON: one JSON object per line, after a `meta` header naming the
exporter, the format version, and the exact Lean githash. Three growing
tables — names, universe levels, expressions — are filled by indexed
lines, and declaration lines point into them. The parser for all of it is
one file (`src/export/parser.ts`), and it validates everything: an index
that was never declared, a duplicate index, an unknown binder kind, each
is a refusal with a reason, not a crash.

Three facts in that paragraph came from reading real bytes with `head`,
next to the format document, and the notebook records the diffs:

- key order inside an object varies — a parser must not depend on it;
- name index 0 and level index 0 are implicit, never declared;
- `natVal` is a JSON **string**: the library contains literals like
  2^128 that no JavaScript number can hold, so the parser uses `BigInt`
  [R: T-LIT](RULES.md#t-lit).

That last point is a border crossing. Literals exist so that a number is
one node instead of a tower of `Nat.succ` a hundred twenty-eight bits
tall, and the kernel computes on them directly — addition, comparison,
bit operations — with explicit size bounds, each bound a refusal rule of
its own [R: RED-NAT](RULES.md#red-nat). Strings are literals too, and their bridge back to
constructor form targets `String.ofList` — a fact this project got right
only by reading `type_checker.cpp` at the export's githash, against the
memory of an older kernel where it was `String.mk` [R: DEFEQ-STRING](RULES.md#defeq-string).

## What "shapes nobody writes" means

Hand-written tests exercise the rules you remembered to test. A real
export exercises the rules as they actually compose: `outParam` wrappers
on binder types that must be stripped before recursor derivation,
universe-polymorphic recursors whose fresh level variable is named by a
convention (`u_1`, with the underscore — chapter 9 is about that
underscore), mutual inductives nested through other inductives, and
quotient declarations that are pure decoration. The arena tarball this
project checks against ships 199 such files: 127 the checker must accept
and 72 it must refuse.

The exercise below feeds ten real-format lines through the actual parser
and checker: an axiom, a definition whose value is a 2^128 literal, and a
line that lies twice — it cites an expression index nobody declared, and
it reuses a name [R: WF-NAME-FRESH](RULES.md#wf-name-fresh). One run, three verdicts.

## Try it

```ts
// Chapter 8 — The real input.
// From here on the exercises use the real checker, not a sketch.
// Run from the repository root: bun book/tryit/ch08.ts

import { ExportParser } from "../../src/export/parser.ts";
import { Checker, tryStep } from "../../src/checker.ts";

// Real lines in lean4export NDJSON format (version 3.1.0). Tables of
// names, levels, and expressions build up by index; a declaration line
// then refers into them. Index 0 is predeclared: the anonymous name,
// the level zero. These facts came from reading the bytes of a real
// export next to the format document — not from either one alone.
const file = [
  '{"meta":{"exporter":{"name":"lean4export","version":"3.1.0"},' +
    '"format":{"version":"3.1.0"},"lean":{"githash":"5045d005","version":"4.34.1"}}}',
  '{"in":1,"str":{"pre":0,"str":"Nat"}}', // name 1 = "Nat"
  '{"in":2,"str":{"pre":0,"str":"big"}}', // name 2 = "big"
  '{"il":1,"succ":0}', // level 1 = succ 0
  '{"ie":0,"sort":1}', // expr 0 = Sort 1, i.e. Type
  '{"axiom":{"name":1,"levelParams":[],"type":0,"isUnsafe":false}}', // axiom Nat : Type
  '{"ie":1,"const":{"name":1,"us":[]}}', // expr 1 = Nat
  // natVal is a STRING in the format: 2^128 does not fit a JSON number.
  '{"ie":2,"natVal":"340282366920938463463374607431768211456"}',
  '{"def":{"name":2,"levelParams":[],"type":1,"value":2,' +
    '"hints":"abbrev","safety":"safe","all":[2]}}', // def big : Nat := 2^128
  '{"axiom":{"name":2,"levelParams":[],"type":9,"isUnsafe":false}}', // two lies at once
];

const parser = new ExportParser();
const checker = new Checker();

for (const [i, line] of file.entries()) {
  const parsed = tryStep(() => parser.processLine(line));
  if (!parsed.ok) {
    const tag = parsed.error.kind === "refusal" ? parsed.error.code : "bug";
    console.log(`line ${String(i + 1).padStart(2)}: refused at parse (${tag})`);
    continue;
  }
  if (parsed.value === null) continue; // a table line, not a declaration
  const decl = parsed.value;
  const name = decl.kind === "inductive" ? "..." : decl.name.toString();
  const checked = tryStep(() => { checker.addDecl(decl); });
  const v = checked.ok
    ? "accepted"
    : `refused (${checked.error.kind === "refusal" ? checked.error.code : "bug"})`;
  console.log(`line ${String(i + 1).padStart(2)}: ${decl.kind} ${name} — ${v}`);
}

console.log(`declarations checked: ${checker.declsChecked}`);
console.log(`format version seen : ${parser.meta?.format.version ?? "none"}`);

// To break it: change natVal's value to a plain JSON number and watch
// precision silently die before the kernel ever sees the term — then
// put it back. The parser must read the bytes the exporter wrote, not
// the bytes a JavaScript number can hold. The last line already breaks
// on purpose: it reuses the name `big` AND cites expression index 9,
// which no line declared. The parser refuses it first (parse), and had
// it slipped through, the environment would refuse the duplicate name.
```

Expected output:

```text
line  6: axiom Nat — accepted
line  9: def big — accepted
line 10: refused at parse (parse)
declarations checked: 2
format version seen : 3.1.0
```
