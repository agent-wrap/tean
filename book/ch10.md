> **Claim.** The last two computation rules are shortcuts, and each one
> is safe only because of a check sitting in front of it.

## Firing iota without looking

Chapter 7 defined a **subsingleton**: a proposition with one constructor
whose every field is forced by the result type. Nothing about such a
value can vary, so nothing about it needs to be read. That allows a
shortcut on iota, called **K-like reduction**: when the major premise is
a proof of a subsingleton proposition, the recursor fires *without
inspecting the proof at all* [R: RED-K](RULES.md#red-k). The type already names the only
constructor the proof could be, so the kernel substitutes that
constructor and carries on. It is chapter 6's proof irrelevance fused
with chapter 9's computation: if all proofs are equal, you may as well
compute with the convenient one.

The shortcut would be a disaster without its guard. "The type names the
only constructor the proof could be" is a claim about *this instance* of
the type, and the kernel must check it: the proof's type has to be
definitionally the constructor's type here, not merely a member of the
same family. Take equality, the canonical subsingleton, whose one
constructor proves `Eq x x` and nothing else. A proof of `Eq a a` may be
replaced by that constructor. A proof of `Eq a b` may not — and if the
guard is dropped, the kernel will substitute a proof of `Eq a a` where a
proof of `Eq a b` was required, which makes everything equal to
everything. The guard is therefore a soundness rule in its own right,
and it carries its own forgery in chapter 14.

## The quotient

The system this book checks ships one primitive family that is not an
inductive type at all: quotient types. Given a type and a relation *r*,
the quotient — written `Quot r` — is the type where related elements are
identified; it is how a library gets integers from pairs of naturals, or
a set from a list.

The kernel builds its four constants itself — the type former, the
wrapper that puts an element into the quotient, the lifter that pushes a
function through it, and the induction principle — and it does so only
after verifying that the equality type already in the environment has
exactly its expected canonical declaration [R: WF-QUOT](RULES.md#wf-quot). That premise is
the whole reason the construction is safe: the quotient's induction
principle is stated in terms of equality, so a forged equality type
would forge the quotient too.

They get one computation rule: lifting a function through the quotient
and applying it to a *wrapped* element just applies the function
[R: RED-QUOT](RULES.md#red-quot). Against anything else — a variable, an unreduced term —
the lift is stuck, and that stuckness is exactly what keeps the quotient
abstract. If the lift could see inside an arbitrary element, the
identification the quotient exists to make would be observable, and
therefore false.

Same transaction as the recursor, twice over: the user proposes, the
kernel constructs, nothing is taken on faith. With this chapter the
theory is complete: eight of the grammar's nine nodes, and every rule
the checker applies to them. The ninth node is a concession to
engineering rather than a piece of theory, and it arrives with the first
real file. What remains is contact with the world.

## Try it

```ts
// Chapter 10 — Two more primitives.
// K-like reduction (iota without looking at the proof) and the
// quotient's one computation rule.

// ---------------------------------------------------------------------
// K-like reduction
// ---------------------------------------------------------------------

// A proposition as the kernel sees it: a head and its arguments.
// `Eq x y` is the running example — one constructor, `refl x : Eq x x`.
interface PropType {
  head: string;
  args: string[];
}
const eq = (x: string, y: string): PropType => ({ head: "Eq", args: [x, y] });
const showT = (t: PropType): string => `${t.head} ${t.args.join(" ")}`;

// What the SOLE constructor's type would be, at this instance. For Eq,
// `refl x` always proves `Eq x x` — the second argument is forced.
function soleCtorType(t: PropType): PropType | null {
  const [x] = t.args;
  return t.head === "Eq" && t.args.length === 2 && x !== undefined ? eq(x, x) : null;
}

const defEqType = (a: PropType, b: PropType): boolean =>
  a.head === b.head && a.args.length === b.args.length && a.args.every((x, i) => x === b.args[i]);

// [R: RED-K] For a subsingleton proposition, iota may fire on a STUCK
// proof: the type alone determines the only constructor the proof could
// be, so the kernel substitutes that constructor without inspecting the
// proof. Proof irrelevance fused with computation.
//
// The guard is the whole safety of the rule: the proof's type must be
// definitionally the constructor's type at this instance.
function kLike(proof: string, type: PropType, guard: boolean): string {
  const inst = soleCtorType(type);
  if (inst === null) return `refused: ${showT(type)} is not a subsingleton`;
  if (guard && !defEqType(type, inst)) return `refused: ${showT(type)} is not ${showT(inst)}`;
  return `fires: ${proof} replaced by (refl ${type.args[0] ?? "?"})`;
}

console.log(`h : Eq a a, guard on  -> ${kLike("h", eq("a", "a"), true)}`);
console.log(`h : Eq a b, guard on  -> ${kLike("h", eq("a", "b"), true)}`);
console.log(`h : Eq a b, guard OFF -> ${kLike("h", eq("a", "b"), false)}`);

// ---------------------------------------------------------------------
// The quotient
// ---------------------------------------------------------------------

// Quot r is the type where r-related elements are identified. The kernel
// builds four constants for it and gives them ONE computation rule.
type QVal =
  | { kind: "mk"; value: string } // an element, wrapped: Quot.mk r a
  | { kind: "opaque"; name: string }; // anything else: a variable, say

// [R: RED-QUOT] Lifting a function through the quotient and applying it
// to a WRAPPED element just applies the function. Against anything else
// it is stuck — which is what keeps the quotient abstract.
function quotLift(fn: string, q: QVal): string {
  return q.kind === "mk" ? `${fn} ${q.value}` : `stuck (${q.name} is not a wrapped element)`;
}

console.log(`Quot.lift f h (Quot.mk r a) ~> ${quotLift("f", { kind: "mk", value: "a" })}`);
console.log(`Quot.lift f h q             ~> ${quotLift("f", { kind: "opaque", name: "q" })}`);

// To break it: pass `false` for the guard on the second line and the
// refusal becomes a fire — the kernel hands back a proof of `Eq a a`
// where a proof of `Eq a b` was asked for, and `a = b` is now provable
// for any a and b. That one boolean is a real weakening flag in this
// project's checker, and chapter 14 runs the forged file through it
// both ways.

export {}; // keeps this file a self-contained module
```

Expected output:

```text
h : Eq a a, guard on  -> fires: h replaced by (refl a)
h : Eq a b, guard on  -> refused: Eq a b is not Eq a a
h : Eq a b, guard OFF -> fires: h replaced by (refl a)
Quot.lift f h (Quot.mk r a) ~> f a
Quot.lift f h q             ~> stuck (q is not a wrapped element)
```
