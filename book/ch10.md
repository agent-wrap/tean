## A dead guess, kept

One magma-expression proof in the local perf suite ran in 10.1 seconds
against 0.16–2.5 for the native structural checkers.
A CPU profile said 24.5% of time sat in one closure. The first guess:
the lift walk inside substitution, repeating work for fresh index
objects. A per-depth lift cache went in — and the number went from
10.1 s to 10.6 s. No change, slightly worse.

The guess was killed by re-profiling with line numbers: the hot closure
was level instantiation on every delta unfold [R: RED-DELTA](RULES.md#red-delta). The real
kernel caches exactly that (its `m_unfold` cache); the port had skipped
it. Adding the one cache the profile actually named: 10.6 s to 4.2 s.
A dead guess plus its autopsy is worth more than the fix, because the
guess was *plausible* — that is the whole argument for measuring.

## The cache that must forget

Reduction rebuilds equal terms as fresh objects, so a cache keyed on
object identity misses forever. One arena test ran out of memory on
identity-keyed caches and finished in 1.4 seconds on hash-bucket caches
with structural equality — the exercise below shows the mechanism
directly. The dual constraint is quieter: the hash must ignore
exactly what equality ignores (binder names and binder annotations
[R: DEFEQ-BINDING](RULES.md#defeq-binding)), or equal terms land in different buckets and the
cache never hits, silently. A hash finds a candidate; equality decides.
The same economy governs beta itself: a whole application spine is
discharged in one substitution pass [R: RED-BETA](RULES.md#red-beta), because one argument
at a time re-walks the body quadratically — confirmed in the kernel
source, ported, and visible in the profile.

## Reading the exit, not the clock

The deep tests do not fail politely. A proof whose input tree is 128
nodes deep can reach a reduction depth of 14,520 — the depth is *made*
by computation, not read from the file. The JavaScript engine this
project tests under pins about eight megabytes of stack (65,483 frames
measured); the engine it ships under, with the stack raised, holds
639,753. One substitution walk was rewritten as an explicit-stack
machine after a measured overflow; its first version popped children in
the wrong order, and the unit tests caught it the same hour.

The method lesson cost a full measurement day: from outside, a stack
crash and a timeout are the same silence. Read the exit code and the
error stream, never the wall clock. And the honest ledger has one open
row: the largest magma test needs 48 GB of heap here against under 10 GB for
every other checker on the arena board. Bytes per node is the suspect;
the heap profile that would convict it has not been taken. The book
does not get to close that row by asserting it.

## Try it

```ts
// Chapter 10 — The cost.
// The cache experiment: identity keys miss what reduction rebuilds.

import { Name } from "../../src/kernel/name.ts";
import { type Expr, Const, App, exprEq } from "../../src/kernel/expr.ts";

// Reduction rebuilds equal terms as FRESH objects. Simulate that:
function build(): Expr {
  const f = new Const(Name.simple("f"), []);
  const a = new Const(Name.simple("a"), []);
  let e: Expr = a;
  for (let i = 0; i < 10; i++) e = new App(f, e);
  return e;
}

const first = build();
const rebuilt = build(); // equal tree, all-new object identities
console.log(`exprEq(first, rebuilt)    : ${exprEq(first, rebuilt)}`);
console.log(`same object?              : ${first === rebuilt}`);
console.log(`hashes agree?             : ${first.hash === rebuilt.hash}`);

// Cache 1: identity-keyed, the JavaScript default.
const identityCache = new Map<Expr, string>();
identityCache.set(first, "cached result");
console.log(`identity cache hit        : ${identityCache.has(rebuilt)}`);

// Cache 2: hash buckets + structural equality, as the kernel's expr_map.
class StructuralMap {
  private buckets = new Map<number, { k: Expr; v: string }[]>();
  set(k: Expr, v: string): void {
    const b = this.buckets.get(k.hash) ?? [];
    if (b.length === 0) this.buckets.set(k.hash, b);
    b.push({ k, v });
  }
  get(k: Expr): string | undefined {
    for (const e of this.buckets.get(k.hash) ?? []) {
      if (e.k === k || exprEq(e.k, k)) return e.v;
    }
    return undefined;
  }
}
const structuralCache = new StructuralMap();
structuralCache.set(first, "cached result");
console.log(`structural cache hit      : ${structuralCache.get(rebuilt) !== undefined}`);

// The measured consequence, from docs/NOTEBOOK.md (2026-10-15): with
// identity-keyed whnf/infer/defeq caches, the arena test
// discarded-argument-match ran out of memory. With structural keys it
// finished in 1.4 seconds. Same algorithm; the only change is the line
// above that can say "yes" to an object it has never met.

// To break it: make StructuralMap.get compare with === only, and watch
// the hit turn false. Then consider the quieter failure: a hash that
// includes what equality ignores (binder names, for instance) sends
// equal terms to different buckets, and the cache silently never hits.
// The hash must forget exactly what the equality forgets.
```

Expected output:

```text
exprEq(first, rebuilt)    : true
same object?              : false
hashes agree?             : true
identity cache hit        : false
structural cache hit      : true
```
