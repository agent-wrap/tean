## New types from outside

Everything so far was fixed grammar. An **inductive type** is different:
the input file *declares* one — a name, some constructors, their types —
and the kernel is being asked to extend its own logic with it. Natural
numbers arrive this way: a type with constructors `zero` and
`succ : t -> t`. So does equality, and so does falsehood (the inductive
type with no constructors at all).

That makes the declaration a contract, and the kernel reviews every
clause before signing [R: WF-IND-SPEC](RULES.md#wf-ind-spec):

- Each constructor is a telescope of arguments — a chain of binders, each
  type free to mention the variables before it — ending in the declared
  type applied to the declaration's **parameters** (fixed across the
  whole declaration) and **indices** (varying per constructor — the
  difference is load-bearing in chapter 7). A list's element type is a
  parameter: every constructor returns a list of the same elements. A
  length-indexed vector's length is an index: "cons" returns a vector one
  longer than its argument's.
- Parameters agree across every type of a mutual declaration (several
  types declared together, allowed to mention each other), and all
  types of the block live in one universe.

Two clauses are famous enough to carry their own names.

## Positivity

A constructor argument may *use* the type being declared — that is what
recursion is — but only in positive position: as the result of the
argument's type, never to the left of an arrow [R: WF-IND-POS](RULES.md#wf-ind-pos). The
forbidden shape, `mk : (t -> Bool) -> t`, hands every element of `t` a
function out of `t`. That injects the function space of `t` into `t`, and
Cantor's diagonal argument turns the injection into a contradiction —
here, a provable False. The exercise below implements the check; it is
about thirty lines, and it stands between the user and that paradox.

## The universe bound

Each constructor argument's type lives in some universe `Sort l'`, and the
declared type lives in `Sort l`. The contract requires
`imax(l', l) <= l` [R: WF-IND-UNIV](RULES.md#wf-ind-univ): a constructor must not smuggle a
bigger universe into a smaller box, or the ladder of chapter 3 collapses
by the back door. The imax (chapter 3's absorbing operation) is what
still lets a *proposition* quantify over anything.

One more clause limits not what a type stores but what it can *compute*:
a proposition with real alternatives — two constructors, or a data-bearing
field — may only eliminate into Prop [R: WF-LARGE-ELIM](RULES.md#wf-large-elim) ("eliminate into a
universe": let the pattern-matching principle chapter 7 derives build its
results there). Chapter 5's proof
irrelevance declared all proofs of it equal; letting a Bool-valued
function distinguish them would contradict that on the spot. The narrow
exception (one constructor, fields forced by the result type) is called a
subsingleton, and it returns with consequences in chapter 7.

## Structures

A one-constructor type earns extras. A **projection** `s.i` extracts field
`i`, typed by walking the constructor's telescope [R: T-PROJ](RULES.md#t-proj), and
reducing when `s` is literally a constructor application [R: RED-PROJ](RULES.md#red-proj).
Definitional equality gains two rules: an element of a non-recursive
structure *is* the constructor applied to its own projections
[R: DEFEQ-ETA-STRUCT](RULES.md#defeq-eta-struct), and a structure with no fields has just one element
[R: DEFEQ-UNIT-LIKE](RULES.md#defeq-unit-like). Each extra is one more thing a forged input can aim
at — the Prop-valued projection tests in the adversary suite of chapter 11
target exactly the clause that keeps projections out of proofs.

## Try it

```ts
// Chapter 6 — Data types are contracts.
// The positivity check, on constructor argument types.

// A constructor argument type, simplified to what the check inspects:
type ArgType =
  | { kind: "self" } // the type being declared, applied to its params
  | { kind: "other"; name: string } // any established type
  | { kind: "arrow"; from: ArgType; to: ArgType }; // a function type

const self: ArgType = { kind: "self" };
const other = (name: string): ArgType => ({ kind: "other", name });
const arrow = (from: ArgType, to: ArgType): ArgType => ({ kind: "arrow", from, to });

function mentionsSelf(t: ArgType): boolean {
  switch (t.kind) {
    case "self":
      return true;
    case "other":
      return false;
    case "arrow":
      return mentionsSelf(t.from) || mentionsSelf(t.to);
  }
}

// Strict positivity: the type being declared may appear as the RESULT of
// an argument's type, but never to the LEFT of an arrow inside it.
function isPositive(t: ArgType): boolean {
  if (!mentionsSelf(t)) return true; // nonrecursive argument: fine
  switch (t.kind) {
    case "self":
      return true; // a plain recursive argument: fine
    case "other":
      return true;
    case "arrow":
      // The domain must not mention the type at all; recurse on the result.
      return !mentionsSelf(t.from) && isPositive(t.to);
  }
}

function show(t: ArgType): string {
  switch (t.kind) {
    case "self":
      return "t";
    case "other":
      return t.name;
    case "arrow":
      return `(${show(t.from)} -> ${show(t.to)})`;
  }
}

function verdict(ctor: string, args: ArgType[]): void {
  const bad = args.find((a) => !isPositive(a));
  const v = bad === undefined ? "accepted" : `refused: ${show(bad)} is not positive`;
  console.log(`${ctor.padEnd(34)} ${v}`);
}

// Nat:  zero : t          succ : t -> t  (argument type is `self`)
verdict("succ (arg: t)", [self]);
// Rose tree: node : (Nat -> t) -> t — self on the RIGHT of the arrow: ok.
verdict("node (arg: Nat -> t)", [arrow(other("Nat"), self)]);
// The forbidden shape: mk : (t -> Bool) -> t — self on the LEFT.
verdict("mk (arg: t -> Bool)", [arrow(self, other("Bool"))]);
// Hidden one level deeper, still caught:
verdict("mk2 (arg: (t -> Bool) -> Nat)", [arrow(arrow(self, other("Bool")), other("Nat"))]);

// To break it: accept `mk : (t -> Bool) -> t` and follow the arithmetic.
// Each element of t now carries a function t -> Bool. That gives an
// injection from functions-out-of-t into t itself, and Cantor's diagonal
// builds the impossible member out of it — in a proof assistant, that
// impossibility is a provable False. Chapter 11 runs this exact attack
// against the real checker, twice: once refused, once with the rule off.

export {}; // keeps this file a self-contained module
```

Expected output:

```text
succ (arg: t)                      accepted
node (arg: Nat -> t)               accepted
mk (arg: t -> Bool)                refused: (t -> Bool) is not positive
mk2 (arg: (t -> Bool) -> Nat)      refused: ((t -> Bool) -> Nat) is not positive
```
