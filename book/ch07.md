# Chapter 7 — Structures and projections

> **Claim.** A one-constructor type earns field access and two new
> equalities, and every extra it earns is one more rule that has to be
> right.

## Why one constructor is special

If a type has a single constructor, then every value of it was built by
that constructor, and the kernel knows the shape of every value in
advance. A type like that is called a **structure**, and the knowledge
buys three things the general case cannot have: you may take a value
apart without a case split, you may put it back together and get the same
value, and — in the extreme case of no fields at all — there is nothing
to take apart in the first place.

Each of those is a rule.

## Taking a value apart

A **projection** `s.i` extracts field `i`. Its typing is the one place in
this chapter that is not obvious, and the reason is chapter 6's
telescope: a later field's type may mention an earlier field. Writing a
dependent pair whose second component's type depends on the first:

```text
   mkDep : (fst : A) -> (snd : B fst) -> Dep
                               '---' the second field's type mentions the first

   so for a value p, the type of p.snd is not "B fst" — there is no
   `fst` in scope — but
                          B p.fst
```

The rule is therefore a walk, not a lookup: take the constructor's
telescope, and replace each earlier binder by a projection of the *same*
value [R: T-PROJ](RULES.md#t-proj). The exercise prints exactly that substitution.

Reduction is the easy half. A projection reduces when — and only when —
its target is literally the constructor applied to arguments: then `s.i`
is argument `i` [R: RED-PROJ](RULES.md#red-proj). Against anything else, a variable most of
all, the projection is *stuck*, and stuck is the ordinary case inside a
proof.

## Putting it back together

Two definitional equalities follow from "there is only one constructor",
and both are completeness rules: a kernel without them refuses true
things and accepts nothing false.

- **Structure eta.** An element of a non-recursive structure *is* the
  constructor applied to its own projections: `p == mkDep p.fst p.snd`
  [R: DEFEQ-ETA-STRUCT](RULES.md#defeq-eta-struct). The judge uses it by expanding whichever side is
  not already a constructor application, and asking again.
- **Unit-like equality.** A structure with no fields has exactly one
  element, so any two of its elements are equal — and the judge may say
  so without inspecting either one [R: DEFEQ-UNIT-LIKE](RULES.md#defeq-unit-like).

Beside the chapter 5 rules they sit naturally: eta for functions says a
function is its own one-step wrapper; eta for structures says a record is
its own field-by-field copy. Same idea, different shape of value.

## What a missing sort check costs

Projections are the one piece of this chapter with a soundness edge, and
the edge is where they meet proof irrelevance. Chapter 5's rule says any
two proofs of one proposition are equal. Projections say any field of a
value may be pulled out. If a value is treated as a proof when it is
actually data, those two rules together will hand you the field of a
value that irrelevance has already declared indistinguishable from any
other — and a contradiction follows.

So everything depends on the predicate that answers *is this a
proposition?* In 2026 the Lean kernel shipped a soundness fix for its
version of exactly that predicate. It inferred the term's type, reduced
it, and checked for `Sort 0`; when the reduced type was a *stuck* term
rather than a sort, it answered **false** — "not a proposition" — where
the honest answer was "this term is ill-formed, refuse it". That wrong
`false` walked past the proof-irrelevance guard on projections. The fix
was to demand a genuine sort and raise a type error otherwise; a second
fix followed days later, because another file had inlined a copy of the
old predicate rather than calling it.

The shape of the mistake is the same one chapter 5 warned about from the
other side. A three-valued question — yes, no, *cannot tell* — collapsed
into two values, and the missing third case was answered with whichever
of the two happened to be the safe-looking default. It was not safe.

## Try it

```ts
// Chapter 7 — Structures and projections.
// A one-constructor type earns three extras: field access, a reduction
// rule for it, and two new ways for the judge to say "equal".

type Expr =
  | { kind: "var"; name: string }
  | { kind: "mk"; struct: string; args: Expr[] } // the constructor, applied
  | { kind: "proj"; struct: string; idx: number; of: Expr }; // field access

const v = (name: string): Expr => ({ kind: "var", name });
const mk = (struct: string, args: Expr[]): Expr => ({ kind: "mk", struct, args });
const proj = (struct: string, idx: number, of: Expr): Expr => ({ kind: "proj", struct, idx, of });

// A structure declaration, reduced to what these rules inspect. A field
// type may mention EARLIER fields, written #0, #1, ...: that is the
// telescope of chapter 6, and it is why projection typing is not a
// table lookup.
interface Struct {
  ctor: string;
  fields: { name: string; type: string }[];
}

const structs = new Map<string, Struct>([
  ["Dep", { ctor: "mkDep", fields: [{ name: "fst", type: "A" }, { name: "snd", type: "B #0" }] }],
  ["Triv", { ctor: "mkTriv", fields: [] }],
]);

// Declared types for the free variables below.
const varTypes = new Map<string, string>([
  ["p", "Dep"],
  ["t1", "Triv"],
  ["t2", "Triv"],
]);

function show(e: Expr): string {
  switch (e.kind) {
    case "var":
      return e.name;
    case "mk":
      return `${structs.get(e.struct)?.ctor ?? "?"}(${e.args.map(show).join(", ")})`;
    case "proj":
      return `${show(e.of)}.${structs.get(e.struct)?.fields[e.idx]?.name ?? String(e.idx)}`;
  }
}

const structOf = (e: Expr): string | undefined =>
  e.kind === "var" ? varTypes.get(e.name) : e.kind === "mk" ? e.struct : undefined;

// [R: T-PROJ] Type a projection by walking the constructor's telescope:
// every earlier field mentioned in the field's type is replaced by a
// projection of the SAME value. `p.snd` is not of type `B #0`; it is of
// type `B p.fst`.
function projType(struct: string, idx: number, of: Expr): string {
  const s = structs.get(struct);
  const field = s?.fields[idx];
  if (s === undefined || field === undefined) throw new Error("no such field");
  let t = field.type;
  for (let i = idx - 1; i >= 0; i--) t = t.replaceAll(`#${i}`, show(proj(struct, i, of)));
  return t;
}

// [R: RED-PROJ] A projection reduces only when its target is LITERALLY a
// constructor application. Against a variable it is stuck, and stuck is
// the normal case.
function reduceProj(e: Expr): Expr | null {
  if (e.kind !== "proj" || e.of.kind !== "mk" || e.of.struct !== e.struct) return null;
  return e.of.args[e.idx] ?? null;
}

// Rebuild a value as "the constructor applied to its own projections".
const etaExpand = (struct: string, e: Expr): Expr =>
  mk(struct, (structs.get(struct)?.fields ?? []).map((_f, i) => proj(struct, i, e)));

function defEq(a0: Expr, b0: Expr): boolean {
  const a = reduceProj(a0) ?? a0;
  const b = reduceProj(b0) ?? b0;
  if (congruent(a, b)) return true;

  const sa = structOf(a);
  const sb = structOf(b);
  // [R: DEFEQ-UNIT-LIKE] A structure with no fields has exactly one
  // element, so any two of its elements are equal — without looking.
  if (sa !== undefined && sa === sb && structs.get(sa)?.fields.length === 0) return true;

  // [R: DEFEQ-ETA-STRUCT] An element of a structure IS the constructor
  // applied to its own projections. Expand the side that is not already
  // a constructor application, and ask again.
  if (a.kind !== "mk" && b.kind === "mk" && sa === b.struct) return defEq(etaExpand(b.struct, a), b);
  if (b.kind !== "mk" && a.kind === "mk" && sb === a.struct) return defEq(a, etaExpand(a.struct, b));
  return false;
}

function congruent(a: Expr, b: Expr): boolean {
  if (a.kind !== b.kind) return false;
  switch (a.kind) {
    case "var":
      return a.name === (b as { name: string }).name;
    case "mk": {
      const bb = b as { struct: string; args: Expr[] };
      return a.struct === bb.struct && a.args.every((x, i) => defEq(x, bb.args[i] ?? x));
    }
    case "proj": {
      const bb = b as { struct: string; idx: number; of: Expr };
      return a.struct === bb.struct && a.idx === bb.idx && defEq(a.of, bb.of);
    }
  }
}

const p = v("p");
const built = mk("Dep", [v("a"), v("b")]);

// Typing: the telescope walk, not a table lookup.
console.log(`type of p.fst                 : ${projType("Dep", 0, p)}`);
console.log(`type of p.snd                 : ${projType("Dep", 1, p)}`);

// Reduction: only against a literal constructor application.
console.log(`${show(proj("Dep", 1, built)).padEnd(30)}~> ${show(reduceProj(proj("Dep", 1, built)) ?? proj("Dep", 1, built))}`);
console.log(`${show(proj("Dep", 1, p)).padEnd(30)}~> stuck (its target is a variable)`);

// The two new equalities.
console.log(`p == mkDep(p.fst, p.snd)      : ${defEq(p, etaExpand("Dep", p))}`);
console.log(`t1 == t2  (Triv has no fields): ${defEq(v("t1"), v("t2"))}`);
console.log(`a == b    (unrelated)         : ${defEq(v("a"), v("b"))}`);

// To break it: delete the DEFEQ-ETA-STRUCT branch and watch the fifth
// line turn false. Nothing unsound happens — a structure value and its
// own field-by-field copy are genuinely the same thing, and refusing to
// see it only costs completeness. Then delete the `e.of.struct !==
// e.struct` guard in reduceProj instead, and nothing visible happens at
// all: the projections here all agree. That silence is the point of
// chapter 13.

export {}; // keeps this file a self-contained module
```

Expected output:

```text
type of p.fst                 : A
type of p.snd                 : B p.fst
mkDep(a, b).snd               ~> b
p.snd                         ~> stuck (its target is a variable)
p == mkDep(p.fst, p.snd)      : true
t1 == t2  (Triv has no fields): true
a == b    (unrelated)         : false
```
