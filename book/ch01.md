> **Claim.** A variable, a function, and a call are a whole language, and
> substitution is its only operation.

## The object under study

A proof assistant is a large program: an editor, an elaborator, a tactic
engine, a compiler. Almost none of it has to be correct. At the bottom sits
one small component, the **kernel**, and the whole system is arranged so
that only the kernel has to be right. Everything above it may produce
garbage, because everything above it must pass its output through the
kernel, and the kernel checks.

The thing above the kernel need not be a person. In October 2026 a
language model wrote about 180 million lines of proof that 239 compiled
programs never crash, a typical proof running to 600,000 lines. The
write-up rests that scale on one sentence: "Claude writes the proof; the
Rocq kernel checks it against the specification." Rocq is a different
proof assistant with a different kernel, but the division of labour is
the one this book builds.

The kernel is a function. It takes data in and returns a verdict. It
performs no I/O, holds no hidden state, and trusts nothing it did not
compute itself. This chapter is about the data, and it starts with the
smallest language that is worth checking, which is also the language the
whole book builds on. Everything the book adds later is a node added to
the grammar below, with a rule added to go with it.

## Three nodes

The data is called a **term** (the words *term* and *expression* are used
interchangeably). A term is a tree, and in TypeScript a tree is a
discriminated union. Three constructors are enough:

- a **variable** `x` — a name;
- a **function** `fun x => e`, called a *lambda*: it binds the name `x`
  and has a body `e`;
- a **call** `f a`, called an *application*: no parentheses, no comma, one
  argument at a time. A function of two arguments is a function that
  returns a function, `fun x => fun y => e`, and `f a b` is `(f a) b`.

Written as a grammar, the way papers write it:

$$e ::= x \;\mid\; \mathrm{fun}\ x \Rightarrow e \;\mid\; e\ e$$

That is the untyped lambda calculus, from 1936. It has no numbers, no
booleans, no types, and it is enough to compute anything. The rest of the
book never replaces it; it adds to it. Variables become numbers in chapter
2, which also adds one bookkeeping node the checker needs and the
language does not. A first, temporary type arrives in chapter 3;
universes, the binder that absorbs that type, and the node that refers to
something already checked, in chapter 4. A local binding joins in chapter
5, field access in chapter 8, and literals in chapter 11. Nine nodes is
the whole grammar, and three of them are these.

## Free and bound

Inside `fun x => f x`, the `x` in the body belongs to the `fun`: it is a
**bound variable**. The `f` belongs to nothing in the term; it is a
**free variable**, and its meaning has to come from outside. Free and
bound describe an *occurrence*, not a name: in `(fun x => x) x` the first
`x` is bound and the last one is free, and they have nothing to do with
each other.

| term | free | bound |
|---|---|---|
| `fun x => x` | none | `x` |
| `fun x => y` | `y` | `x`, though the body never uses it |
| `fun x => fun y => x y z` | `z` | `x`, `y` |
| `(fun x => x) x` | the last `x` | the `x` inside the `fun` |
| `fun x => (fun x => x) x` | none | both, by different binders; the inner `fun` shadows the outer |

A term with no free variables is **closed**. A closed term means something
on its own. An open term means something only once somebody says what its
free variables stand for, and chapter 3 is where that somebody appears.

Two terms that differ only in the names of their bound variables are the
same function: `fun x => x` and `fun y => y`. The lambda-calculus word for
that sameness is **alpha-equivalence**, and a checker must treat
alpha-equivalent terms as equal, which with names means every comparison
has to reason "up to renaming".

## Substitution, and the trap

The one operation is **substitution**, written $e[a/x]$ and read "*e*
with *a* for *x*": replace every free occurrence of `x` in `e` by the
term `a`. Three cases, one per node:

1. a variable: if it is `x`, the result is `a`; otherwise unchanged;
2. a call: substitute into both halves;
3. a function `fun y => body`: if `y` is `x`, stop — every `x` inside is
   bound by this `fun` and is not the `x` being replaced; otherwise
   substitute into the body.

Case 3 has a trap, and it is the reason this chapter exists. Substitute
`y` for `x` in `fun y => x`. The naive answer is `fun y => y`, the
identity function. But `fun y => x` was the constant function, the one
that ignores its argument and returns whatever `x` stands for — and `x`
stood for `y`, a free variable, which has now been grabbed by the `fun`
it walked under. The term changed meaning, and nothing crashed. The name
for this is **capture**, and the fix with names is to rename the binder
first: `fun y1 => y`.

That rename is not a detail. Every operation that moves a term under a
binder has to perform it, and every one of them is a place to get it
wrong. Chapter 2 removes the names, and with them the trap.

## Beta

Apply a function by substituting its argument into its body:

$$(\mathrm{fun}\ x \Rightarrow e)\ a \quad\text{steps to}\quad e[a/x]$$

This one rule is called **beta**, and it is the whole of computation in
the untyped calculus. `(fun x => x) y` steps to `y`; `(fun x => fun y =>
x) y` steps to `fun y1 => y`, with the rename from the previous section
doing its job. A checker runs this rule for a reason chapter 5 explains;
for now it is enough that beta is substitution with a trigger.

## Running it

A call whose function is a lambda is called a **redex**, short for
reducible expression. Beta fires one redex at the root. To run a whole
program, look for a redex anywhere in the tree, fire it, and repeat until
none is left. A term with no redex is in **normal form**, and the normal
form is the program's answer. That loop is the entire interpreter for
this language, and the exercise below has it in twenty lines:
`step` finds the leftmost, outermost redex and fires it, and `normalize`
calls `step` until it returns nothing.

Two things appear the moment the loop exists. First, the constant
function applied twice, `(fun x => fun y => x) a b`, takes two steps and
answers `a`, and every step was a substitution. Second, there is a term
that steps to itself:

$$(\mathrm{fun}\ x \Rightarrow x\ x)\ (\mathrm{fun}\ x \Rightarrow x\ x)$$

Fire its one redex and the result is the same term, so the loop never
ends. This is not a bug in the interpreter. The calculus can express
every computation, including the ones that do not stop, and no
interpreter can tell in advance which is which. The exercise caps the
loop at a thousand steps for that reason. A checker inherits the
problem: chapter 5 calls an interpreter from inside type checking, and
chapter 13 measures what that costs on real input.

A checker also needs less than the full normal form. It asks whether two
terms are equal, and for that it usually only has to reduce until the
outermost node is settled, never under a binder and never inside an
argument until something demands it. Chapter 5 names that stopping
point and builds the function.

## One term, several readings

The grammar has no numbers, yet the calculus is supposed to compute
anything. A number has to be encoded. The usual encoding, due to Church,
makes *n* the function that applies `f` to `x` *n* times:

```text
1    = fun f => fun x => f x
2    = fun f => fun x => f (f x)
3    = fun f => fun x => f (f (f x))
plus = fun m => fun n => fun f => fun x => m f (n f x)
```

`plus` applies `f` *n* times to `x`, then *m* more times. Run `plus 1 2`
with the loop above and it stops at `fun f => fun x => f (f (f x))`,
which is 3. Every step along the way was a beta.

Now look at `1` again. Nothing in `fun f => fun x => f x` says *one*.
Read it as code and it is *apply*: take a function and an argument, and
call the function on the argument. Chapter 3 will give it a type, and
once chapter 4 reads a type as a statement, the same term proves the
oldest rule in logic: if A gives B, and A holds, then B holds. It is one
term with three readings, and the term doesn't choose between them.

Zero makes the point more sharply. The usual booleans pick one of two
arguments, and `false` is `fun x => fun y => y`. Rename its binders and it
is `0`, which is `fun f => fun x => x`. The two are alpha-equivalent, so to
a checker they are the same term. Add `false` to 3 and the loop answers
3, with no complaint, because to the calculus nothing went wrong. The
meaning was never in the term. It was in the encoding the reader had in
mind, and the untyped calculus has nowhere to write that encoding down.

The rest of the book is, in large part, the work of writing it down.
Chapter 2 removes the names, and `0` and `false` become literally one
tree. Chapter 3 adds types, a record of how a term is meant to be used.
Chapter 7 goes further: a number and a boolean stop being encodings and
become data types that the input file declares, and that a checker can
tell apart.

## Try it

```ts
// Chapter 1 — Three nodes.
// A variable, a function, a call — and substitution is the whole meaning.
// Paste this whole file into any TypeScript playground and run it.

type Expr =
  | { kind: "var"; name: string } // x
  | { kind: "lam"; binder: string; body: Expr } // fun x => body
  | { kind: "app"; fn: Expr; arg: Expr }; // fn arg

const v = (name: string): Expr => ({ kind: "var", name });
const lam = (binder: string, body: Expr): Expr => ({ kind: "lam", binder, body });
const app = (fn: Expr, arg: Expr): Expr => ({ kind: "app", fn, arg });

function show(e: Expr): string {
  switch (e.kind) {
    case "var":
      return e.name;
    case "lam":
      return `(fun ${e.binder} => ${show(e.body)})`;
    case "app":
      return `(${show(e.fn)} ${show(e.arg)})`;
  }
}

// A variable occurrence is free when no enclosing `fun` binds its name.
function freeVars(e: Expr): Set<string> {
  switch (e.kind) {
    case "var":
      return new Set([e.name]);
    case "lam": {
      const inner = freeVars(e.body);
      inner.delete(e.binder); // the binder closes over its own name
      return inner;
    }
    case "app":
      return new Set([...freeVars(e.fn), ...freeVars(e.arg)]);
  }
}

let fresh = 0;
const freshName = (base: string): string => `${base}${++fresh}`;

// e[a/x]: replace every FREE occurrence of x in e by a.
function subst(e: Expr, x: string, a: Expr): Expr {
  switch (e.kind) {
    case "var":
      return e.name === x ? a : e;
    case "app":
      return app(subst(e.fn, x, a), subst(e.arg, x, a));
    case "lam": {
      if (e.binder === x) return e; // x is rebound here: nothing inside is free
      if (freeVars(a).has(e.binder)) {
        // The trap. `a` mentions this binder's name, so pushing `a` under
        // the binder would capture it. Rename the binder first.
        const y = freshName(e.binder);
        return lam(y, subst(subst(e.body, e.binder, v(y)), x, a));
      }
      return lam(e.binder, subst(e.body, x, a));
    }
  }
}

// Beta: apply a function by substituting the argument into its body.
function beta(e: Expr): Expr {
  if (e.kind === "app" && e.fn.kind === "lam") return subst(e.fn.body, e.fn.binder, e.arg);
  return e;
}

// One step anywhere in the term, leftmost-outermost first.
// Returns null when there is no redex left: the term is in normal form.
function step(e: Expr): Expr | null {
  switch (e.kind) {
    case "var":
      return null;
    case "lam": {
      const body = step(e.body);
      return body === null ? null : lam(e.binder, body);
    }
    case "app": {
      if (e.fn.kind === "lam") return beta(e);
      const fn = step(e.fn);
      if (fn !== null) return app(fn, e.arg);
      const arg = step(e.arg);
      return arg === null ? null : app(e.fn, arg);
    }
  }
}

// Run: step until nothing steps. A cap, because some terms never stop.
function normalize(e: Expr, cap = 1000): string {
  for (let i = 0; i < cap; i++) {
    const next = step(e);
    if (next === null) return show(e);
    e = next;
  }
  return `(still stepping after ${cap} steps)`;
}

// fun x => f x  — f is free, x is bound.
const t1 = lam("x", app(v("f"), v("x")));
console.log(`${show(t1)}   free: ${[...freeVars(t1)].join(", ")}`);

// (fun x => x) y  steps to  y
console.log(show(beta(app(lam("x", v("x")), v("y")))));

// (fun x => fun y => x) y: the constant function, applied to y. It must
// step to a function that ignores its argument and returns y.
const k = lam("x", lam("y", v("x")));
console.log(show(beta(app(k, v("y")))));

// Run a whole program: k a b, two steps, and the answer is a.
console.log(normalize(app(app(k, v("a")), v("b"))));

// Numbers, encoded: n is "apply f to x, n times". plus runs n, then m.
const f = v("f");
const x = v("x");
const one = lam("f", lam("x", app(f, x)));
const two = lam("f", lam("x", app(f, app(f, x))));
const three = lam("f", lam("x", app(f, app(f, app(f, x)))));
const plus = lam("m", lam("n", lam("f", lam("x", app(app(v("m"), f), app(app(v("n"), f), x))))));
console.log(normalize(app(app(plus, one), two)));

// false picks its second argument. Nothing stops it being added to 3,
// and the answer is 3: to the calculus, false is just another term.
const no = lam("x", lam("y", v("y")));
console.log(normalize(app(app(plus, three), no)));

// A term that steps to itself forever. The cap is the only thing that
// brings this line back.
const w = lam("x", app(v("x"), v("x")));
console.log(normalize(app(w, w)));

// To break it: in subst, delete the `if (freeVars(a).has(e.binder))`
// branch and rerun. The third line becomes (fun y => y) — the identity
// function. The y that was free walked under a `fun y` and was captured.
// Nothing crashed. Chapter 2 deletes the names so the trap cannot exist.

export {}; // keeps this file a self-contained module
```

Expected output:

```text
(fun x => (f x))   free: f
y
(fun y1 => y)
a
(fun f => (fun x => (f (f (f x)))))
(fun f => (fun x => (f (f (f x)))))
(still stepping after 1000 steps)
```
