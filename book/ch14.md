> **Claim.** Soundness is tested with forgeries: every rule is defined by
> what it refuses.

## Three oracles

Three kinds of evidence check a checker, and each finds what the others
cannot. *Ground truth* — a real export — finds shapes nobody writes by
hand (chapter 11). *Coverage* finds paths no data took. And a *red team*
finds checks that are absent — the failure mode the first two cannot even
represent, because a missing check passes every test that exists. The
arena's `bad/` suite is a curated red team: 72 files, each one a forgery
aimed at a specific rule, each one refused by this checker for the coded
reason the registry names.

## The forgery gate

This book's registry (book/rules.json) goes one step further than
refusing: for each weakenable rule it keeps the demonstration that the
rule is *load-bearing*. A build flag disables exactly one named rule;
a test asserts the forgery is refused with the rule on and ACCEPTED with
it off, both against the real checker. The exercise runs one of each
kind. In the registry's terms:

- [R: WF-IND-POS](RULES.md#wf-ind-pos) off: a negative inductive type is accepted — the gate
  to Cantor's False (chapter 7).
- [R: WF-IND-UNIV](RULES.md#wf-ind-univ) off: a constructor smuggles a universe — Girard's
  ladder breach (chapters 4, 7).
- [R: WF-REC-DERIVE](RULES.md#wf-rec-derive) off: a forged recursor is installed as an induction
  principle (chapter 9).
- the defeq guard inside K-like reduction [R: RED-K](RULES.md#red-k) off (via its own
  weakening flag, RED-K-GUARD): a proof is replaced by a constructor of
  the wrong instance.

One honesty note the gate forced into the open: this checker refuses
most of these files *twice*, once by the named rule and once by the
derive-and-compare net, so the weakened runs for the inductive-family
forgeries also trust the export, as the historical attacks assumed. The
test file says so in its own comments. Defense in depth is worth having;
it is not an excuse to leave a layer unverified.

## Completeness is not soundness

The posttest at the gate of this book asks, for an unseen rule: does the
kernel that lacks it accept a false proof? The answer is not always yes,
and the difference is the sharpest idea in the chapter. A theorem whose
type is not a proposition is refused as a matter of hygiene
[R: WF-THM-PROP](RULES.md#wf-thm-prop) — but its value is still checked, so dropping the rule
accepts a well-typed non-theorem and proves nothing false. The exercise
shows that acceptance too. Compare the zeta rule of chapter 5: a kernel
without it refuses some *true* proofs and accepts no false ones — a
completeness loss, not a breach. Soundness rules get forgeries; hygiene
and completeness rules get explanations. A reviewer who can make that
call about a rule they have never seen has finished this book's job.

## Try it

```ts
// Chapter 14 — The adversary.
// Run one forgery against the real checker, twice: with the rule, and
// without it. Run from the repository root: bun book/tryit/ch14.ts

import { checkFile } from "../../src/main.ts";
import { weaken, restoreAllRules } from "../../src/kernel/weaken.ts";

async function verdict(path: string): Promise<string> {
  const r = await checkFile(path, false);
  if (r.failures.length === 0) return `ACCEPTED (${r.declsChecked} declaration${r.declsChecked === 1 ? "" : "s"})`;
  const f = r.failures[0];
  if (f === undefined || f.failure.kind !== "refusal") return "CHECKER BUG";
  return `refused [${f.failure.code}] at ${f.decl}`;
}

// A negative inductive type — chapter 7's forbidden shape, as real
// export bytes from the arena's bad suite. Accepting the declaration is
// the whole breach: Cantor's construction then derives False from it.
const indNeg = "book/forgeries/WF-IND-POS.ndjson";
console.log(`positivity on : ${await verdict(indNeg)}`);
weaken("WF-IND-POS"); // the named rule...
weaken("WF-REC-DERIVE"); // ...and trust the export, as the attack assumes
console.log(`positivity off: ${await verdict(indNeg)}`);
restoreAllRules();

// A theorem whose type is not a proposition. Also refused — but dropping
// THIS rule yields no proof of False, and the book must say which is which.
const nonPropThm = "book/forgeries/WF-THM-PROP.ndjson";
console.log(`thm-prop on   : ${await verdict(nonPropThm)}`);
weaken("WF-THM-PROP");
console.log(`thm-prop off  : ${await verdict(nonPropThm)}`);
restoreAllRules();

// To break it: this file IS the controlled break. The uncontrolled
// version is a kernel that never had the rule, and no test that notices.
// Every soundness rule in the registry carries a forgery like the first
// one; every hygiene rule carries an explanation like the second. A rule
// with neither is a rule nobody has defined yet.
```

Expected output:

```text
positivity on : refused [inductive] at indNeg
positivity off: ACCEPTED (1 declaration)
thm-prop on   : refused [typeMismatch] at nonPropThm
thm-prop off  : ACCEPTED (1 declaration)
```
